# Controlled Server-Backed EPUB Reader

## Summary
- Replace the current `epubjs`-driven EPUB path at `/books/:id` with a controlled reader that loads one spine section at a time, shows a nested nav sidebar, preserves browser TTS, and keeps PDF/non-EPUB behavior unchanged.
- Make the backend the source of truth for EPUB structure: parse OPF + nav/NCX, normalize the final chapter/section tree in spine order, serve section HTML, and stream EPUB assets through reader-specific endpoints.
- Use a sandboxed same-origin iframe fed via `srcdoc` for section rendering so EPUB CSS/images/fonts/SVG stay isolated from app CSS while the parent app still controls navigation, TTS, themes, and progress.

## Public APIs And Types
- Add `GET /api/v1/books/:id/reader/manifest` returning a `ReaderManifest` with:
  - `sections[]` in canonical spine order
  - nested `nav[]` items with `label`, `section_id`, optional `fragment`, and `children[]`
  - `first_section_id`
- Add `GET /api/v1/books/:id/reader/sections/:section_id` returning a `ReaderSection` with:
  - `id`, `title`, `section_index`, `prev_section_id`, `next_section_id`
  - `html` as rewritten section markup ready for iframe `srcdoc`
- Add `GET /api/v1/books/:id/reader/assets/*path?rt=...` to stream same-book assets referenced by section HTML/CSS.
- Keep `GET/PUT /api/v1/books/:id/progress`, but change the reader payload/response to chapter-based fields:
  - `section_id: string`
  - `section_progress: number` in `[0,1]`
  - `block_index?: number | null`
  - `percentage: number`
  - `rating?: number`
- Remove `cfi` from the client/API contract for the new reader. The DB column may remain unused in v1 to avoid a destructive migration, but the new code should not depend on it.
- Add client types for `ReaderManifest`, `ReaderNavItem`, `ReaderSection`, and the updated `ReadingProgress` shape.

## Implementation Changes
- EPUB parsing:
  - Extend the Go EPUB layer beyond metadata extraction to parse OPF manifest/spine plus EPUB 3 nav docs with NCX fallback.
  - Resolve every nav href against the OPF base path, map each target onto a spine section plus optional fragment, and use spine order as the canonical sort key.
  - Preserve nested TOC structure where possible, dedupe duplicate targets, and append missing linear spine items as root leaves.
  - Derive fallback titles from nav labels first, then the first heading in the section XHTML, then the file basename.
- Section delivery and asset auth:
  - Fetch section HTML over Axios with bearer auth, then render it via iframe `srcdoc`.
  - Rewrite section HTML on the server:
    - local asset URLs become signed reader asset URLs
    - cross-section links become app-handled targets carrying `section_id` and `fragment`
    - same-section anchors stay in-document
    - remote URLs, scripts, and inline event handlers are stripped
  - Use a short-lived signed reader token (`rt`) scoped to `user_id + book_id + expiry` for asset URLs, because normal iframe/img/css requests cannot send the Axios bearer header.
  - Keep the iframe sandboxed without script execution; allow same-origin access so the parent can inspect scroll position and readable blocks.
- Reader UI:
  - Split the current monolithic EPUB path into a reader shell, nav sidebar, section frame, TTS logic, and theme logic.
  - Desktop gets a persistent left nav; mobile gets a drawer. The active nav item follows the loaded section and in-section fragment.
  - Section navigation is explicit: sidebar click, internal cross-section links, and prev/next section controls all replace the current continuous multi-section scroller.
  - Progress save/restore uses the current section plus the nearest readable block index and section scroll ratio. Overall `percentage` is derived from `(section index + section progress) / total sections`.
- TTS and themes:
  - Preserve browser Web Speech API TTS with current controls: voice, rate, pitch, volume, start-at-paragraph, pause, resume, stop.
  - Operate on readable blocks inside the iframe document; when auto-advance is enabled, finish the current section, load the next section, and continue reading there.
  - Ship theme presets `light`, `dark`, and `custom`.
  - The custom theme editor includes color controls for page background, body text, muted chrome text, link/accent, and TTS highlight.
  - Persist theme/TTS prefs in local storage only, then inject theme CSS both into the app shell and into the iframe document.
- Cleanup:
  - Remove the `epubjs` dependency and all `CFI`/rendition/page-turn code once the new reader is wired in.
  - Add `NetworkOnly` service-worker rules for the new reader manifest/section/asset endpoints so signed URLs and section HTML are never cached by Workbox.

## Test Plan
- Backend unit tests for EPUB normalization:
  - EPUB 3 nav with nested sections
  - EPUB 2 NCX fallback
  - broken TOC order corrected by spine order
  - missing TOC entries filled from spine
  - duplicate hrefs/fragments handled deterministically
- Backend handler tests for:
  - auth required on manifest/section
  - signed reader token accepted for assets
  - expired or wrong-book token rejected
  - asset path traversal rejected
  - image/CSS/font content types preserved
  - scripts/event handlers/remote URLs removed from section HTML
  - cross-section links rewritten correctly
- Integration tests with synthetic EPUB fixtures covering nested nav, anchors, images, and CSS.
- Client verification:
  - `go test ./...`
  - `npm run type-check`
  - `npm run build`
- Manual QA on at least three real EPUBs:
  - EPUB 2 NCX-only book
  - EPUB 3 nested TOC book
  - image-heavy/illustrated book
  - Confirm nav order, section-only scrolling, image/font rendering, internal links/footnotes, TTS paragraph selection, next/prev section behavior, theme persistence, and unchanged PDF behavior.

## Assumptions And Defaults
- Hard cutover is intentional: existing CFI-only saved positions are not migrated; those books reopen at the start in the new reader.
- Custom themes are browser-local and are not synced to the server.
- Scripted EPUB content is intentionally unsupported; local book assets are supported, remote network content is blocked.
- No client-side EPUB ZIP parsing remains in v1; the backend is the only EPUB structure parser.
