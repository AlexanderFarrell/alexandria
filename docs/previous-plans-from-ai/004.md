# Alexandria Library Enhancement Plan

## Context

The current LibraryView is a bare-bones book grid with search and upload. The user wants a richer library experience: browsing by author/genre via a sidebar, a detail modal with full metadata, inline metadata editing, per-user book ratings, sort controls, and a full book lists feature (create lists, add books to lists). This touches both backend (new DB columns/tables, new API endpoints, extended existing endpoints) and frontend (new components, refactored views).

## Key Implementation Notes

1. **`json_each` for genres**: `ListGenres` and the genre filter in `book_repo.go` both use SQLite's `json_each` virtual table. This requires modernc.org/sqlite ≥ 3.38 — the project uses v1.23.1 (SQLite 3.43) so it's safe. Use raw GORM queries for these.

2. **Rating-sort JOIN**: When `SortBy == "rating"`, conditionally LEFT JOIN `reading_progress` filtered by `UserID`. Handler must extract user ID from JWT context and put it in `BookFilter`. Without a `UserID`, fall back to `created_at`.

3. **Rating nil-preservation**: In `reader.go`'s `SaveProgress`, only set `progress.Rating = input.Rating` when `input.Rating != nil`. This ensures calling save-progress without a rating never wipes out a previously stored rating.

4. **`/books/authors` before `/:id`**: Fiber matches routes in registration order. The new named routes must be registered before `/:id` or "authors"/"genres" will be parsed as book IDs.

5. **List ownership**: Every `ListService` method taking a `listID` must fetch the list, verify `list.UserID == userID`, and return `domain.ErrForbidden` otherwise. No exceptions.

6. **Genre/tag text input**: `BookEditModal` displays genres/tags as comma-separated strings and splits on save. Trimming whitespace is important.
