# Plan: PDF Support — Metadata, Cover Extraction, Viewer, Refresh Button

## Context
Alexandria already accepts PDF uploads but does nothing with them beyond storing the binary. Users have PDFs already on the server with no metadata or covers. The goal is to:
1. Extract metadata (title, author, subject, keywords) from PDFs on upload
2. Extract a cover image by rendering the first page via `pdftoppm` (poppler)
3. Add a "Refresh Metadata" button to re-run extraction on existing books
4. Add an in-browser PDF viewer in ReaderView using a native `<iframe>`

---

## Backend

### 1. Add `pdfcpu` dependency
```
go get github.com/pdfcpu/pdfcpu
```
Used for reading the PDF Information Dictionary (/Title, /Author, /Subject, /Keywords, /CreationDate).

### 2. Create `infra/pdf/parser.go`
Implements `ports.BookParser` for PDF files.

**`ParseMetadata(ctx, filePath)`**:
- Open PDF with `pdfcpu/pkg/api.ReadContextFile(filePath)`
- Read `ctx.Info` (map[string]string): Title → book.Title, Author → book.Author, Subject → book.Description, Keywords → split into book.Metadata.Tags, CreationDate → book.Metadata.PublishedAt
- Return partial Book (non-fatal on parse errors)

**`ExtractCover(ctx, filePath, destPath)`**:
- Check if `pdftoppm` is in PATH via `exec.LookPath`; return nil (skip) if absent
- Run: `pdftoppm -f 1 -l 1 -r 96 -png <filePath> <tmpPrefix>`
- This writes `<tmpPrefix>-1.png`
- Load the PNG with Go's `image` package, encode as JPEG to `destPath` using `image/jpeg`
- Return nil on any failure (non-fatal)

### 3. Create `infra/parser/dispatch.go`
A `DispatchParser` wrapping both parsers, dispatching by file extension. This avoids changing the `BookService` constructor signature:

```go
type DispatchParser struct {
    parsers map[domain.FileType]ports.BookParser
}
// ParseMetadata and ExtractCover delegate to the right parser based on filepath ext
```

### 4. Wire up in `cmd/server/main.go` (or wherever the app is composed)
Replace `epub.NewParser()` injection with `parser.NewDispatchParser(epub.NewParser(), pdf.NewParser())`.

### 5. Fix `app/services/book.go` — remove the EPUB-only guard
Lines 92–101 and 121–125: change the `if fileType == domain.FileTypeEPUB` guard to call `s.parser.ParseMetadata` for all file types (the DispatchParser handles routing). Same for `ExtractCover`.

### 6. Add `RefreshMetadata` to `app/services/book.go`
```go
func (s *BookService) RefreshMetadata(ctx context.Context, id string) (*domain.Book, error)
```
- GetByID to get existing book (preserve Tags — user may have set them)
- Open the stored file via `s.store.Open`
- Call `s.parser.ParseMetadata` with the abs path
- Re-run `s.parser.ExtractCover`; update `book.CoverPath` if successful
- Merge extracted metadata into existing book (only overwrite non-empty extracted fields; preserve tags)
- `s.books.Update` and return updated book

### 7. Add `POST /api/v1/books/:id/refresh` route & handler
- **`api/rest/handlers/books.go`**: add `RefreshMetadata(c *fiber.Ctx)` — calls service, returns `{"book": book}`
- **`api/rest/routes.go`**: add `books.Post("/:id/refresh", bookH.RefreshMetadata)`

### 8. Add `?inline=true` to `ServeContent`
In `ServeContent` handler: if `c.QueryBool("inline")`, use `Content-Disposition: inline` instead of `attachment`. This enables the iframe viewer.

## Frontend

### 1. `client/src/api/books.ts`
- Add `refreshMetadata(id: string): Promise<Book>` → `POST /api/v1/books/{id}/refresh`
- Add `getContentUrl(id: string, inline = false): string` helper that returns the URL (with `?inline=true` as needed) — used by the iframe viewer

### 2. `client/src/stores/books.ts`
- Add `refreshBookMetadata(id: string)` action: calls API, updates the book in `books` array in place

### 3. `client/src/components/BookDetailModal.vue`
Add a "Refresh metadata" button in the right-actions row (next to Edit):
- Only shown for `epub` and `pdf` (not `url`)
- Calls `booksStore.refreshBookMetadata(book.id)`
- Shows loading state; on success the reactive `book` prop updates automatically via the store

### 4. `client/src/views/ReaderView.vue`
Replace the current PDF fallback block (lines 119–126) with:
```html
<div v-else-if="book && book.file_type === 'pdf'" class="pdf-viewer-container">
  <iframe :src="pdfContentUrl" class="pdf-iframe" />
  <div class="pdf-toolbar">
    <button @click="downloadBook">Download PDF</button>
  </div>
</div>
```
- `pdfContentUrl` = `/api/v1/books/{id}/content?inline=true` (needs auth token appended or a cookie-based approach)
- Since the API uses JWT in Authorization header (not cookies), the iframe approach won't work directly — instead, **fetch the PDF as a blob URL** (same approach as `getContentBlob`) and set `<iframe :src="blobUrl">`
- The existing `getContentBlob` already handles auth; create a blob URL from it and bind to the iframe src
- Add CSS: `.pdf-iframe { width: 100%; height: 100%; border: none; flex: 1 }` and `.pdf-viewer-container { display: flex; flex-direction: column; height: 100% }`
