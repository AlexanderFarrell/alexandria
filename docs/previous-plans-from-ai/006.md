# Public Deployment Hardening Plan

## Summary
- Target deployment is a single-owner internet-exposed service behind Docker + NGINX, not a tenant-isolated multi-user product.
- Do not ship the current build publicly as-is.
- Ship only after closing the registration/library exposure gap, removing insecure defaults, hardening HTTP behavior, and tightening runtime/deployment posture.
- Do not add per-user book ownership in this phase. Instead, explicitly enforce single-user/shared-library modes at the app boundary.

## Key Changes
### 1. Enforce explicit account modes
- Add `REGISTRATION_MODE` config with values `disable | single | multi`; default to `single`.
- `single` behavior:
  - If user count is `0`, allow one bootstrap registration.
  - If user count is `1`, reject further registration.
  - If user count is `>1`, fail startup with a clear operator error.
- `disable` behavior: always reject registration.
- `multi` behavior: allow multiple accounts, but document clearly that this is a shared-library mode, not isolated multi-tenant mode.
- Add a small public auth-status endpoint, for example `GET /api/v1/auth/status`, returning `registration_mode` and `can_register`.
- Update the login page to fetch auth status on mount, hide the Register tab when `can_register=false`, and show single-owner/bootstrap messaging instead of open signup.
- Update README and deploy docs to stop advertising unconditional public registration.

### 2. Remove insecure startup defaults
- Make the server fail fast if `JWT_SECRET` is unset, matches the known placeholder, or is below a minimum length.
- Remove the fallback secret from `docker-compose.yml`; require it via env file or Docker secret.
- Keep TLS/HSTS at NGINX, but document that Alexandria must only be exposed behind HTTPS in production.

### 3. Harden HTTP behavior
- Replace wildcard CORS with opt-in origin allowlisting via `CORS_ALLOW_ORIGINS`.
- If the app is served same-origin behind NGINX, disable CORS middleware entirely by default.
- Add basic security headers in-app: `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`.
- Keep CSP/HSTS/rate limiting in the reverse proxy config and document the exact expected headers/rules there.
- Stop returning raw internal errors on 500s. Keep detailed errors in logs; return generic `"internal server error"` to clients.

### 4. Fix file delivery and resource-risk issues
- Replace full `io.ReadAll` book delivery with streaming or `SendFile` from local storage so downloads do not allocate the full book in memory.
- Keep the current upload size config, but document a lower recommended public default and reverse-proxy body limit.
- Add reverse-proxy rate limits for `/api/v1/auth/*`, uploads, and large content downloads.
- Keep file-type validation extension-based for this phase, but add lightweight signature checks for PDF/EPUB headers to reject obvious bad uploads.

### 5. Improve deploy/runtime posture
- Add `.dockerignore`.
- Pin the runtime base image to a specific Alpine version instead of `latest`.
- Run the container as a non-root user and make `/data` the only writable path.
- Add a readiness endpoint, for example `GET /readyz`, that verifies DB open plus data-dir accessibility; keep `/health` as a shallow liveness check.
- Document backup/restore as a host/volume snapshot of `/data`; do not build an in-app backup scheduler in this phase.

## Test Plan
- Go tests for `REGISTRATION_MODE`:
  - `single` allows first registration only.
  - `single` rejects second registration.
  - `disable` always rejects registration.
  - `multi` still allows multiple registrations.
  - startup validation fails when `single` mode sees more than one stored user.
- API tests for auth-status endpoint and hidden registration behavior.
- API tests proving 500 responses no longer leak internal file paths or DB details.
- Server/integration tests for book download and cover serving after the streaming change.
- Existing validation gates remain required: `go test ./...`, frontend type-check, frontend production build.
- Manual release checks:
  - bootstrap first account on an empty DB
  - confirm Register is hidden afterward
  - confirm same-origin deploy works behind NGINX with strict origin settings
  - confirm backup/restore docs work on a real `/data` snapshot

## Assumptions
- Reverse proxy termination, TLS certificates, HSTS, and request rate limiting are handled by NGINX, not by the Go app.
- SQLite remains the production datastore for this phase because the target is single-owner/hardened hobby prod.
- `multi` mode is intentionally shared-library mode only; true per-user library isolation is out of scope for this plan.
- Token storage can remain bearer-based for this phase once wildcard CORS is removed; moving to HttpOnly cookie sessions is recommended later, but not required to ship this single-owner release.
