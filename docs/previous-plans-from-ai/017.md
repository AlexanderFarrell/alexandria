# MCP Book Search Result Sizing

## Summary
- Change Alexandria MCP book search to use an MCP-specific default page size of `100` when `books_search` is called without `limit`.
- Enforce a hard maximum of `200` results per `books_search` call, even if a client requests more.
- Keep pagination intact with `page` and `limit`; this is a bounded expansion of the existing behavior, not a switch to unbounded “return all”.

## Key Changes
- Update MCP pagination normalization in [server.go](/home/alexander/Projects/alexandria/api/mcpserver/server.go):
  - Default `limit` becomes `100` for MCP book search.
  - Clamp requested `limit` to `200`.
  - Leave non-positive `page` behavior unchanged: default to page `1`.
- Keep the underlying repository/service interfaces unchanged.
  - This is an MCP-layer policy only.
  - REST `/api/v1/books` pagination behavior stays as-is unless explicitly changed later.
- Update MCP-facing docs:
  - [mcp-surface.md](/home/alexander/Projects/alexandria/docs/alexandria-mcp-skill/references/mcp-surface.md)
  - [SKILL.md](/home/alexander/Projects/alexandria/docs/alexandria-mcp-skill/SKILL.md)
  - [README.md](/home/alexander/Projects/alexandria/README.md)
  - Document that `books_search` defaults to `100` and caps at `200`.

## Test Plan
- Update MCP search tests to expect default `limit=100` when omitted.
- Add coverage for explicit `limit` handling:
  - omitted `limit` returns `100`
  - `limit <= 0` returns `100`
  - `limit=50` returns `50`
  - `limit=500` is clamped to `200`
- Add at least one happy-path test with more than 20 books to confirm the MCP layer can return substantially more results in one call.
- Keep existing HTTP MCP route/auth tests unchanged except for any assertions that mention the old default limit.

## Assumptions
- The observed “9 books” issue is likely caused by the MCP host or model behavior, not Alexandria’s backend cap.
- Bounded larger responses are preferable to unbounded “all results” because MCP tool output competes for model context and token budget.
- No new tool is needed for now; `books_search` remains the single discovery tool.
